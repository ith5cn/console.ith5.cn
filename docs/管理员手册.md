# ITH5 管理员手册

面向负责维护团队 AI 资源的人。后台所有页面都对应 `/v1` 接口，脚本化操作看 [开发规格](./开发规格.md) §1。

---

## 0. 从零开始

登录页用邮箱密码登录后，如果账号还不属于任何组织，会直接进入「新建组织」；已有组织的账号在选组织时也能新建。
建组织的人就是它的 owner。服务端首个账号仍可用 `-init-owner` 创建。

之后按顺序：建项目（可选建团队）→ 加成员或接入 OIDC → 「成员与设备 → 接入码 → 生成」，把弹出的
`teamai init --server … --code …` 一行发给员工。员工在自己的项目目录里跑这一行就接入了，不需要 Git。

## 1. 模型

```
组织 ──▶ 团队 ──▶ 项目           层级：谁必须拿到
   │
   └─ 权限组 ──授权──▶ 成员 / 项目 / 全组织    可选包：谁额外拿到
```

- **组织级**资源发给全员，**团队级**发给团队成员，**项目级**发给项目成员。同名资源越具体的层级越优先。
- 放进任一**权限组**的资源不再按层级自动分发，只经授权分发。权限组适合「后端工具包」这类可选内容，可设到期时间。
- 角色只有四种：组织的 owner / admin / member / viewer，团队与项目各自的 admin / member。细粒度权限由角色推导，不单独配置。

| 你想做 | 谁能做 |
|---|---|
| 创建变更集 | 目标层级的任何成员 |
| 审核 | 目标层级的 admin，以及团队 / 项目额外指定的审核人；不能审自己的 |
| 发布 | 目标层级的 admin；admin 建变更集时可勾选「快速通道」跳过审核，仍留审计 |
| 分享经验 | 任何成员，直接发布 |
| 管成员 | 组织 admin 管组织；团队 admin 管团队；项目 admin 管项目 |
| 看审计、改身份源、改组织策略 | 组织 admin / owner |

viewer 只能浏览，所有写请求被拒绝。

## 2. 发布内容

### 新建

**内容库 → 新建**。选类型、层级（组织 / 团队 / 项目）、名字，填正文。保存即创建一个草稿变更集并提交审核；
admin 可以直接发布。

| kind | 是什么 | 入口文件 |
|---|---|---|
| skill | 多文件目录，Claude 判断相关时自动用 | `SKILL.md` |
| rule | 单文件规范 | `RULE.md` |
| doc | 单文件文档，名字可带子路径 | 文件本身 |
| agent | teamai 的 YAML 规格，下发时按工具渲染 | `agent.yaml` |
| hook | 一条 hook 声明，可附脚本 | `hook.yaml` |
| mcp | 一个 MCP server 定义 | `mcp.yaml` |
| env | 一个环境变量。名字像凭据（TOKEN、SECRET、PASSWORD、KEY…）的必须写 `secret: true` 且不带 value，值由成员在本机设置 | `env.yaml` |
| claudemd | CLAUDE.md / AGENTS.md 片段 | `CLAUDE.md` |
| culture | 每层一份的团队文化 | `culture.md` |
| policy | 每层一份的 sharing 策略，字段级合并取更严者 | `policy.yaml` |
| learning | 经验，走知识库页面 | `LEARNING.md` |

发布前服务端会逐个扫描资源里的文本文件（包括 skill 的附属脚本），命中密钥模式直接拒绝并指出文件与行号。

成员也可以在本机改完后用 `ith5-materialize push` 推上来，效果与后台新建一样：生成变更集进入审核。

### 变更集

**变更集**页有三个视图：我的、待我审核、全部。详情里能看 diff、审核记录，以及提交 / 批准 / 打回 / 拒绝 / 发布 / 取消。

- 提交后内容有改动，之前的审核自动作废。
- 需要几个人批准由**组织策略**里的 `required_approvals` 决定，默认 1。
- 发布时如果基线已经被别人发布过：改动互不重叠自动放行，重叠则报 412，作者重建。
- 发布是一个事务，一次可以跨多个项目，客户端只会看到旧版本或新版本。

### 回滚

**发布历史 → 选一次发布 → 回滚**。回滚会生成一个新的变更集，把当时的内容重新发布一遍，历史不改写。

## 3. 把内容给到人

- **层级落点**决定谁必须拿到。项目级资源不需要任何授权，项目成员自动得到。
- **权限组 → 装配**把资源放进组；**授权策略 → 新增**把组授权给成员、项目或全组织，可设到期。到期的条目保留行以便审计。
- 单个资源也可以直接授权，留给一次性场景。

## 4. 成员、设备与接入

### 入职

**成员与设备 → 新增成员**填邮箱、姓名、角色、初始密码。接了 OIDC 的组织不需要这一步，首次登录自动建账号，分组映射决定角色。

不会 Git 的成员用**接入码**：**成员与设备 → 接入码 → 生成**，指定项目、有效期、可用次数，弹窗给出完整的一行命令
`teamai init --server <地址> --code <码>`。成员在项目目录里跑它：登录、绑定项目、同步一步完成。

### 设备

设备授权流登录时终端显示验证码，成员在后台 `/activate` 输入。**成员与设备 → 设备**能改名、撤销任何人的设备。

### 离职

**成员与设备 → 停用**。一个事务内：refresh 令牌全部撤销，设备与绑定标记撤销，下一次同步返回空清单，客户端卸载本机内容。

> 准确的说法是「切断续期，不保证擦除」。清理依赖对方主动同步，所以敏感能力必须放在服务端 API 之后。

## 5. 知识库

- **知识库**：浏览、搜索、分享经验。正文命中密钥模式（token、私钥、连接串、Bearer、`key=value`）直接拒绝并指出位置。
- **归档**：作者可归档自己的，admin 可归档任何。归档就是发布一个 tombstone。
- **晋升**：把一条经验变成正式的 rule / doc / skill，生成草稿变更集走正常审核。
- **知识库健康**：召回趋势、最常召回、沉默的、建议归档、建议晋升。阈值在**组织策略**里调。
- **周报**：会话、成功率、轮次、时长、费用、人工纠正，与上周对比；数据来自客户端上报，不含任何提示词。

组织策略里 `learnings_review` 打开后，分享经验也要走审核。

## 6. 审计

| 视图 | 答什么问题 |
|---|---|
| 管理动作 | 谁在什么时候改了什么：发布、授权、停用、策略 |
| 分发记录 | 谁拿了哪个版本；`conflict_skipped` 表示被成员本地改动挡住 |
| 执行记录 | 谁用什么工具动了哪个仓库的哪个文件；只有元数据 |

服务端对上报做白名单解析，提示词、输出片段、绝对路径、完整命令行没有落地字段。

## 7. 身份源

**身份源**页配置 OIDC issuer、client id / secret、scopes，并把 IdP 分组映射到组织角色、团队或项目。
登录时按最新的 groups claim 重算角色。回调地址是 `<ITH5_BASE_URL>/v1/auth/oidc/callback`。

IdP 不可用时新登录与写操作拒绝，已签发的 access token 在 15 分钟内仍能读快照。

**对账**：改了分组映射之后，已登录过的成员要等下次登录才会重算角色。身份源页底部的「对账」列出这些成员和差异，
逐个或一键应用；每次应用记一条审计。服务端每天也会统计差异数写日志，但不会自动改。

---

## 7b. 保留期与清理

**组织策略 → 上报数据保留月数**决定会话摘要、用量、执行记录保留多久（默认 13 个月）。服务端每天自动清理一轮，
也清过期的去重账本与令牌；owner 可在同一页「立即清理」。审计事件、分发记录、发布与版本永不清理。
备份与恢复见 [运维-备份与恢复.md](./运维-备份与恢复.md)。

## 8. 排障

| 现象 | 排查 |
|---|---|
| 成员说没拿到某个资源 | 资源是否已发布；层级是否覆盖他；放进权限组的资源是否已授权；看**审计 → 分发记录** |
| 同步一直受阻 | 分发记录里看 `conflict_skipped` 的路径，让成员删掉本地改动的文件 |
| 发布报 412 | 基线过期且与别人的发布重叠，作者基于当前版本重建变更集 |
| 分享经验被拒 | 正文含疑似密钥，按提示改掉再交 |
| 成员设备 401 | 设备或账号已撤销，在**成员与设备**里确认 |

## 9. 部署

| 项 | 生产要求 |
|---|---|
| `ITH5_JWT_SECRET` | ≥32 字节随机值，进 secret manager |
| 数据库 | 托管 PostgreSQL，改掉默认密码 |
| `ITH5_BASE_URL` | 真实 HTTPS 域名，OIDC 回调与设备授权链接用它 |
| TLS | 必须；令牌在 Authorization 头里传输 |
| 演示数据 | 生产不要跑 `-seed` |

```sh
docker build -t ith5-server .
docker run -e ITH5_DATABASE_URL=… -e ITH5_JWT_SECRET=… -e ITH5_BASE_URL=https://console.example -p 8080:8080 ith5-server
```

首个 owner 用 `-init-owner` 配合 `ITH5_INIT_*` 变量创建。迁移每次启动自动执行；探活打 `GET /healthz`，
指标在 `GET /metrics`（Prometheus 文本，可用 `ITH5_METRICS_TOKEN` 加 Bearer 保护）。
