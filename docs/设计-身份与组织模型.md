## 1. 身份：账号与组织成员分离

一个人可以属于多个组织，身份键是 `(issuer, subject)`，邮箱只做展示与联系。

```
accounts   id, issuer, subject, email, name, created_at, disabled_at
           UNIQUE(issuer, subject)
users      现有字段全部保留（org_id, email, role, status, password_hash …）
           + account_id  uuid NOT NULL REFERENCES accounts
           语义变为「某账号在某组织的成员记录」
```

- 密码登录：issuer = `local`，subject = 邮箱。
- OIDC 登录：issuer = IdP 的 issuer URL，subject = `sub` claim。
- 登录流程：先解析 account，列出其在各组织的 `users` 行，选组织进入。
- **token 里继续放 user_id**（组织内），现有 JWT、刷新、设备绑定逻辑不变。

迁移：为每个现有 `users` 行生成 `accounts(local, email)`，同邮箱跨组织的合并为一个 account。

## 2. 角色

```
users.role            owner | admin | member | viewer     组织级（现有）
team_members.role     admin | member                      新增
project_members.role  admin | member                      现有表加字段
```

不再增加角色种类。细粒度权限由三层角色推导，不单独存储。

## 3. 权限推导

| 权限 | 谁有 |
|---|---|
| `project:read` | 项目成员；所属团队成员；组织 admin / owner |
| `resource:write`（创建变更集） | 目标层级的成员。**普通成员可以提，但必须经审核**；不能 fast_track |
| `review:decide` | 目标层级的 admin + 该层级额外指定的 reviewer；**不能是作者** |
| `release:publish` | 目标层级的 admin。有此权限者可 fast_track |
| `learning:contribute` | 任何成员（直接发布，见知识文档） |
| `membership:manage` | 组织 admin 管组织成员；团队 admin 管团队；项目 admin 管项目 |
| `telemetry:write` | 任何未撤销的设备 |
| `audit:read` | 组织 admin / owner |
| `organization:manage` | owner |
| `device:manage` | 自己的设备；组织 admin 可撤销任何人的 |
| viewer | 只读浏览后台，所有写请求在中间件拒绝（现有） |

"目标层级的成员"：org 级 = 全组织成员；team 级 = 团队成员；project 级 = 项目成员。

reviewer 名单：

```
reviewers   level (team | project), owner_id, user_id
```

## 4. 设备、绑定与接入

现有设备授权流（`device_codes`、`refresh_tokens`）保留，是 #341 P1 的核心。补三项：

**接入码**（#341 旅程 J2）

```
enrollments   id, org_id, project_ids uuid[], created_by, code_hash, expires_at,
              max_uses int DEFAULT 1, used_count int DEFAULT 0, revoked_at
device_codes  + enrollment_id uuid NULL
```

管理员生成一次性、限时、限定项目的接入码。员工 `teamai init` 输入码 → 走设备流登录 →
成功后自动创建 binding 到这些项目。过期 / 已用尽 / 已撤销的码不能创建绑定。

**refresh 重用检测**

```
refresh_tokens   + family_id uuid
```

轮换后旧 token 再被使用 → 撤销整个 family。access token 有效期 15 分钟。

**撤销的传播**（一个事务内）

停用 account 或 users → 该用户全部 refresh 撤销 → 其设备标 `revoked_at` →
其 binding 标 `revoked` → 下次 snapshot 返回空清单（用户停用）或 401（设备撤销）。
本地清理依赖客户端下次同步，不承诺远程擦除。

## 5. 身份适配器

```go
type Identity struct {
    Issuer, Subject, Email, Name string
    Groups []string
}

type IdentityProvider interface {
    Kind() string                                          // "local" | "oidc"
    BeginBrowser(state string) (redirectURL string, err error)    // 授权码 + PKCE
    CompleteBrowser(code, state string) (Identity, error)
    VerifyPassword(email, password string) (Identity, error)      // 仅 local 实现
}
```

一期实现 `local` 与通用 `oidc`（授权码 + PKCE；CLI 走现有设备流，浏览器端完成 OIDC）。
企业私有协议、SCIM 留接口不实现。原始企业 token 只停留在适配器内，不落库。

**组到角色映射**

```
idp_group_mappings   org_id, idp_group, target (org | team:<id> | project:<id>), role, priority
```

- 首次登录：验证 issuer 后创建 account，按映射创建 `users` / `team_members` / `project_members`。
- 后续登录：按最新 `groups` claim 重算角色。
- 定时对账：对比 IdP 用户组与本地角色，生成差异报告，管理员确认后应用。

**IdP 不可用时**：新登录、刷新、写操作全部拒绝；已签发的 access token 在 15 分钟内仍可读 snapshot。
