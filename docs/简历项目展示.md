# ITH5 简历项目展示

> 以下内容基于当前改版后的仓库生成，定位为“面向 teamai-cli 的企业级 AI 编码资源管理后端”。正文可直接粘贴到简历；投递不同岗位时，可按后文建议取舍。

## 推荐版（适合后端 / Go / 平台工程岗位）

### ITH5 — 企业级 AI 编码资源管理与分发平台

**项目角色：** 核心开发 / 全栈开发  
**技术栈：** Go、Chi、PostgreSQL、pgx、React、TypeScript、OIDC、JWT、Docker、Prometheus

**项目简介：**  
面向 `teamai-cli` 设计并实现自托管管理后端，将原先依赖 Git 仓库的 Skill、Rule、Agent、MCP、Hook 等团队 AI 资源，升级为支持组织统一治理、审核发布、权限控制、客户端同步和知识沉淀的平台。员工可通过设备授权或接入码完成零 Git 接入，服务端以单 Go 二进制交付，外部仅依赖 PostgreSQL。

**核心工作与成果：**

- 重新设计 Git 仓库式资源分发流程，将 clone、branch、MR、merge、pull 分别映射为设备授权、变更集、审核、原子发布和快照同步，打通 `teamai-cli` 的初始化、拉取、推送、贡献及删除链路，降低非 Git 用户的接入门槛。
- 设计组织—团队—项目三级多租户模型及角色权限体系，支持 OIDC 登录、IdP 分组映射、接入码、Refresh Token 轮换与重用检测；成员停用可在单事务内撤销设备、令牌和工作区绑定，保证权限变更及时生效。
- 实现变更集状态机与多项目发布机制，覆盖草稿、提交审核、批准、发布、取消和回滚；结合内容摘要、审批失效、`ETag / If-Match` 乐观锁及发布冲突检测，保证并发修改下的审核有效性和跨项目发布原子性。
- 构建基于 SHA-256 的内容寻址同步协议：按组织 / 团队 / 项目层级解析 11 类资源，以 revision 清单哈希识别版本，通过 `ETag / 304` 避免重复传输，并利用 tombstone、哈希校验和可见性校验处理覆盖、删除与 Blob 安全下载。
- 完善平台工程能力，统一实现幂等键、游标分页、限流、客户端版本协商、密钥扫描、审计日志、数据保留任务、IdP 对账、Prometheus 指标及健康检查；建设 100+ 个 Go / 前端自动化测试用例，覆盖认证、撤销、资源解析、发布冲突、同步缓存、上报去重等关键路径。
- 使用 React + TypeScript 搭建嵌入式管理后台，覆盖成员、团队、项目、资源库、变更审核、发布历史、身份源、知识库、周报、权限组和审计等管理场景；前端构建产物与数据库迁移一并嵌入 Go 服务，实现单镜像部署。

**技术栈：** Go / PostgreSQL / React / TypeScript / OIDC / JWT / Docker / Prometheus

- 面向企业 AI 编码配置治理，将基于 Git 的 Skill、Rule、Agent、MCP 等资源工作流重构为“变更集—审核—原子发布—客户端同步”，支持设备授权和接入码零 Git 接入。

## 一句话版本（项目列表 / 招聘平台）

基于 Go、PostgreSQL 与 React 实现 teamai-cli 的企业级管理后端，将 Git 式 AI 资源分发升级为支持多租户权限、变更审核、原子发布、内容寻址同步、知识沉淀与审计的零 Git 管理平台。

## 面试开场版本（约 40 秒）

ITH5 是我围绕 teamai-cli 改版的一套企业级管理后端。它解决的核心问题是：团队原来通过 Git 仓库管理 Skill、Rule、Agent、MCP 等 AI 编码资源，这对非 Git 用户有门槛，也缺少统一的权限、审核和审计。我把 Git 中的分支、MR、合并和拉取抽象成服务端的变更集、审批、原子发布和哈希快照同步，同时设计了组织—团队—项目三级权限、OIDC 身份接入和设备授权。技术上比较有挑战的是跨项目发布的一致性、审核摘要防篡改、层级资源解析，以及成员停用后的令牌和设备撤销传播。

## 可重点展开的技术难点

1. **审核与并发一致性：** 变更内容生成稳定 digest，审核决定绑定 digest；内容一旦编辑，原审核自动失效。发布时锁定内容头，只对真正重叠的过期修改报冲突，避免无关变更互相阻塞。
2. **层级资源解析：** 按 project > team > org > 权限组进行资源合并，最具体层级优先；通过 tombstone 表达删除，policy 类型采用字段级“从严合并”，避免简单覆盖带来的权限放宽。
3. **同步效率与安全：** revision 由规范化快照计算，未变化直接返回 304；内容按 SHA-256 寻址，下载前校验当前用户是否仍能看到引用该 Blob 的资源，避免知道哈希即可越权读取。
4. **身份撤销传播：** 将账号、组织成员和设备身份分离，Refresh Token 使用 family 轮换并检测旧 Token 重用；成员停用时在同一事务内撤销令牌、设备和绑定，使下一次同步返回空清单并触发客户端卸载。

## 投递方向微调

- **Go 后端岗：** 保留状态机、事务、乐观锁、内容寻址、身份与撤销四个重点，前端描述压缩为一句。
- **平台工程 / DevOps 岗：** 强调单二进制、嵌入迁移、PostgreSQL 单依赖、Docker、Prometheus、健康检查、备份恢复和数据保留。
- **全栈岗：** 保留推荐版最后一条，并补充 React 管理后台覆盖的核心页面和端到端业务闭环。
- **安全方向岗位：** 强调多租户隔离、OIDC、Refresh Token 重用检测、Blob 可见性校验、密钥扫描、审计与最小化遥测。
