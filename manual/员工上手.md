# ITH5 员工上手

公司把 skill / rule / agent / MCP / hook / 经验统一发到你的电脑上。你用的是 teamai-cli，不需要 Git，不需要知道任何仓库地址。

---

## 装

需要 Node 20 以上。管理员会告诉你装哪个版本的 teamai-cli（带 `--server` 的版本）。

```sh
npm install -g teamai-cli
```

## 接入

在你的项目目录里：

```sh
teamai init --server https://<服务端地址>
```

终端显示一个验证码，用公司账号在浏览器里登录并输入验证码。然后选这个目录要跟哪个项目（只有一个时自动选）。
接着它会自动同步并装进 `.claude/`、`settings.json`、`.mcp.json`。这个目录不需要是 git 仓库。

管理员给了接入码的话：

```sh
teamai init --server https://<服务端地址> --code ABCD-1234
```

项目由接入码决定，连选都不用选。

`--agent cursor` 可以指定别的工具；不指定时按你机器上已装的工具来。

## 改了想推回去

```sh
teamai push                    # 扫描你改过或新建的 skill / rule / agent / env，提交审核
teamai push --dry-run          # 只看会提交什么
teamai remove rules old-rule   # 删除也走审核
```

推送会生成一个变更集并交给审核人，终端里会给出后台链接。同一批内容再推一次会合并进同一个变更集，不会开两个。
新建的资源默认落到当前绑定的项目；跟了多个项目时用 `--project <slug>` 指定。

## 日常

| 什么时候 | 做什么 |
|---|---|
| 打开 AI 工具 | 什么都不用做，会话启动时自动同步 |
| 想立刻同步 | `teamai pull` |
| 想看自己装了什么 | `teamai status` |
| 想分享一条经验 | `teamai contribute --file 文件.md --title 标题`，直接发布；含密钥会被拒 |
| 换项目 | 在该目录重跑 `teamai init --server …`，重新选项目 |
| 换了新电脑 | 重跑「接入」 |
| 提示客户端版本过低 | 更新 teamai-cli |

未变化时同步什么也不做（服务端返回 304），可以放心多跑。

## 常见问题

**同步说某项「受阻」（conflict_skipped）**

目标文件已经存在，且内容既不是上一版也不是新版，说明你自己改过。**你的改动不会被覆盖**，公司的新版本也不会下来。
想拿新版就删掉那个文件再同步。

**提示 401 或「设备已撤销」**

管理员撤销了这台设备或停用了你的账号。本地文件保留，同步停止。找管理员确认。

**同步后清单是空的，本机内容被卸载了**

账号被停用时服务端会返回空清单。这是预期行为。

**连不上服务端**

已装的内容照常可用，恢复网络后再同步即可。

## 记录了我什么

透明起见：

**会记录**

- 你拿到了哪个内容的哪个版本，同步应用结果
- 会话摘要：用了哪些工具、轮次、时长、token 用量
- 经验被召回、被点赞的次数
- 执行记录：工具名、仓库、相对路径、命令名

**不会记录**

- 你和 AI 说的话、模型的回复
- 文件内容、diff、完整命令行、环境变量
- 本机绝对路径

这些字段在服务端没有落地的地方：客户端就算发了，服务端解析时也直接丢弃。

## 离职时

管理员停用账号后，你下次同步会收到空清单，公司分发的内容自动卸载。你自己的文件不受影响。

自己主动清：`teamai uninstall` 清本机内容；设备凭据在 `~/.teamai/server-credentials.json`，删掉即登出，管理员也可以在后台撤销这台设备。
